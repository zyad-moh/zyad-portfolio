LLM Verifiers & Outcome Reward Model

Phi-3-miniGSM8KLLM VerificationORMPyTorchHugging Face

An end-to-end experimentation project exploring inference-time verification for mathematical reasoning. Using Phi-3-mini on GSM8K, the workflow evaluates sampling-based methods, constructs a labeled solution dataset, and trains an Outcome Reward Model (ORM) to score and rank candidate solutions.

View Repository on GitHub ↗
Experimental scope: This is a learning and experimentation project, not a benchmark claim. The ORM dataset contains 100 questions and 400 candidate solutions, so reported evaluation results should be interpreted in the context of this small sample.
Project Objectives
▸Evaluate the base model: Establish a greedy-decoding baseline on GSM8K and inspect how reliably Phi-3-mini solves mathematical reasoning problems.
▸Explore inference-time verification: Experiment with pass@N, majority voting (self-consistency), and an LLM-as-a-judge setup.
▸Build an ORM dataset: Generate four candidate solutions per question and label each candidate by comparing its extracted final answer with the GSM8K ground truth.
▸Train and evaluate a verifier: Train a lightweight classification head over a frozen Phi-3-mini backbone, address class imbalance, tune the threshold on validation data, and evaluate ranking with Best-of-4.

ORM Dataset Construction

Four sampled solutions were generated for each of the first 100 questions in the GSM8K training split. Each extracted final answer was compared with the ground-truth answer. The label represents outcome correctness, not step-by-step reasoning quality.

▸Frozen language model: Phi-3-mini-4k-instruct provides contextual representations; its backbone parameters remain frozen during ORM training.
▸Masked mean pooling: Last-layer token representations are averaged while the attention mask excludes padding tokens, producing one 3,072-dimensional vector per candidate.
▸Lightweight trainable head: A Linear(3072 → 1) layer contains 3,073 trainable parameters and predicts a correctness logit for each question–solution pair.
▸Training setup: The classifier head is optimized with AdamW and BCEWithLogitsLoss. The notebook checks tokenization, forward pass, pooling, loss, and an optimizer step before full training.
Data Splitting & Imbalance Handling

An initial sequential split produced a heavily skewed validation set, making accuracy misleading. The data was then split at question level so all four candidates belonging to a question remain in the same partition. Questions were stratified by the number of incorrect candidates, using random seed 42.

Evaluation Results

The decision threshold was tuned using the validation set only. A threshold of 0.4 gave the best validation Macro F1 among the tested thresholds and was then used for final test evaluation.

Classification

Evaluates whether each candidate's predicted probability falls on the correct side of the selected threshold.

Best-of-4 Ranking

Scores the four candidates for a question and selects the highest-scoring one. This evaluates candidate selection rather than threshold-based classification.

Limitations & Interpretation
  • Small evaluation set: The test set contains only 13 questions and 52 candidate solutions, including questions where all four candidates are already correct.
  • Best-of-4 result: The 13/13 result is encouraging but optimistic; the mixed-candidate subset is a more informative check, and a larger test set is needed.
  • Limited generalization: The same 100 questions provide the ORM training and evaluation partitions, and Phi-3-mini is also the candidate generator. These experiments do not establish generalization to other models or problem distributions.
  • Outcome-level supervision: The ORM is trained on complete candidate solutions labeled by final-answer correctness. It is not a Process Reward Model (PRM) and does not provide step-level reasoning verification.
